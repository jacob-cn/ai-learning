Stage 2

Structured output & prompt engineering

A chatbot returns prose. Real software needs data. This stage was about making the model hand back something my code can parse — and learning that "please return JSON" is a request, not a contract.

What I built

An Android code reviewer in TypeScript. You paste a chunk of Kotlin, and it returns a structured review: a score out of ten, a verdict, and a list of issues each tagged with a severity and category. Not a paragraph of feedback — a JSON object I can render, sort, or gate a CI check on.

View the demo & README on GitHub

Key concepts

Structured output

Structured output means asking the model to return data in a defined shape — here, a specific JSON object. The trick that makes it reliable lives in the system prompt: I don't describe the format in prose, I paste the literal JSON skeleton I want back — fields and allowed values and all — and end with "Return ONLY the JSON. No markdown, no explanation, no backticks."

Prompt engineering

That precision is prompt engineering: wording instructions so the model behaves predictably. A vague ask gets vague, inconsistent output; an exact schema plus explicit "do not" rules is the difference between parseable-every-time and works-in-the-demo.

Gotchas & lessons

A prompt is a nudge, not a guarantee

I told the model, in capital letters, to return only JSON with no backticks. It mostly obeyed — and then occasionally wrapped the whole thing in a ```json fence anyway, breaking the parse. The lesson isn't "write a firmer prompt." It's that an instruction is a strong nudge the model usually follows but can ignore.

The real guarantee is code. I strip any stray fences before parsing, keep the parse in a try/catch, and only trust the result once it has parsed into a typed object. The prompt aims for the right output; the code is what makes the program safe when the aim is off.

Since then: the API can enforce it

This demo uses the prompt-only approach because it shows the underlying problem. But most providers now offer enforced structured output — Gemini's responseSchema / JSON mode, OpenAI's structured outputs — where you hand the API a schema and the reply is guaranteed to parse and match it: no stray fences, no defensive stripping. When you build for real, reach for that and check your provider's structured-output docs; treat the prompt-and-parse version here as the lesson in why that feature exists.

System prompts stack in layers

Writing my own system prompt made me realize it's rarely the only one. By the time a request reaches the model, several layers can be stacked on top of each other — and you control only some of them.

  • You can sometimes inspect the app layer. VS Code's Copilot Chat, for instance, has a "Show Chat Debug View" that reveals the exact context it sends; some other tools expose it only in their logs, and many don't expose it at all. Where you can see it, it's a great way to learn how a good agent prompt is written.
  • You usually can't touch the provider layer. Safety and behaviour instructions injected on the backend aren't visible or editable — so never assume the model is seeing only your prompt.
  • Layers can be attacked. Crafted user input can try to override or reveal a system prompt — "prompt injection" / jailbreaking. The defensive takeaway: never put a secret in a system prompt, and never assume its rules are unbreakable.

The core mechanic, in code

Two halves: a system prompt carrying the exact schema, and a parse step that sanitizes before it trusts. Here's the second half — the part that turns "the model usually returns JSON" into "my program always gets a typed object or a handled error."

demos/02-code-reviewer-typescript/code-reviewer.ts 
interface ReviewResult {        # the exact shape I expect back
  summary: string;
  score: number;
  issues: CodeIssue[];
  verdict: "approve" | "approve_with_changes" | "request_changes";
}

async function reviewCode(code: string): Promise<ReviewResult> {
  const result = await model.generateContent(code);
  const text = result.response.text();

  const cleaned = text.replace(/```json|```/g, "").trim();
  return JSON.parse(cleaned) as ReviewResult;
}
  1. The interface is a contract written in the code, not in the prompt: a valid review must have a summary, a numeric score, a list of issues, and one of three exact verdict strings.
  2. The model is called with the pasted code; what comes back is just text — untrusted until proven otherwise.
  3. The .replace(...) line strips any markdown fences the model added despite being told not to. This single line is the "nudge, not guarantee" lesson made concrete.
  4. JSON.parse(...) as ReviewResult is the moment of trust: the raw text only becomes a typed object if it actually parses. If it doesn't, this throws — a handled error, never a silent bad value.
