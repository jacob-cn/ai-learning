Glossary

Every term used across the stages, defined once and used consistently, listed A–Z. Where a term has a common synonym, it's noted on first mention, then dropped in favor of the canonical name.

Agent loop
The cycle that makes tool use useful: send request → model requests a tool → execute it → return the result → repeat until the model answers. First appears: Stage 3
Chunking
Splitting a long document into smaller, overlapping pieces before embedding, so retrieval can return a relevant section rather than a whole file. First appears: Stage 4
Context compaction
Summarizing the earlier conversation into a compact form as the context window fills — keeping decisions, facts, and current state while dropping verbatim detail — so a session continues smoothly instead of erroring or bluntly dropping history. Also called context compression. First appears: Stage 3
Context window
The total amount of text a model can consider in one request — the conversation history, system prompt, retrieved documents and the new message all share this single budget. First appears: Stage 1
Embedding
A numeric vector representation of text. Similar meanings produce similar numbers, which is what makes semantic search possible. First appears: Stage 4
Extended thinking
A trained model capability that produces private reasoning before any answer. It's a toggle on a capable model, not a prompt you write, and is distinct from ReAct's visible Thought: lines. First appears: Stage 6
Generator/verifier split
A separate, deliberately skeptical model checks whether a claimed "done" is actually correct — because a model grading its own work tends to overpraise it. First appears: Stage 6
Harness
Everything around a model that makes it a working agent: tools to act, memory to remember, a loop to keep going, verification to check the work, and guardrails to stay safe. First appears: Stage 6
Inference
Running a trained model to produce any output at all. The opposite of "training" — not the opposite of "thinking." First appears: Stage 6
Loop engineering
An outer system that runs an agent's harness on a schedule across many runs — finding its own work and deciding when to stop. Very new and contested terminology. First appears: Stage 6
MCP
The Model Context Protocol — an open standard that lets any AI app connect to any tool or data server without writing custom integration code for each one. First appears: Stage 5
MCP host / client / server
Three roles in one sentence: the host is the app (e.g. Claude Desktop); the client is built into the host and speaks the protocol; the server is what you build and expose. First appears: Stage 5
Prompt engineering
Wording instructions so a model behaves predictably — being explicit about format, constraints and what not to do. First appears: Stage 2
RAG
Retrieval-Augmented Generation: retrieving the most relevant chunks of your data and injecting only those into the prompt, instead of dumping everything into context. First appears: Stage 4
Rate limits (RPM / TPM / RPD)
Three independent API caps — requests per minute, tokens per minute, and requests per day — each of which fails differently and is fixed differently. First appears: Stage 6
ReAct
"Reason + Act" — a prompted pattern that makes the model state a brief reason before each tool call, turning an opaque decision into visible text. First appears: Stage 6
Spec-Driven Development
Writing a structured, testable specification of intent before an agent acts — a separate axis from how autonomous the agent is. First appears: Stage 6
Structured output
Asking a model to return data in a defined format (typically JSON) instead of free-form prose, so your code can parse it. First appears: Stage 2
System prompt
A persistent instruction set, kept separate from the back-and-forth of the conversation, that sets the model's role and rules. First appears: Stage 1
Token
The basic unit of text an LLM processes — a subword piece from a fixed vocabulary (common words are one token; rarer ones split into several), averaging ~4 characters of English. Pricing and context limits are both counted in tokens. First appears: Stage 1
Tool use (a.k.a. function calling)
Giving a model a set of described functions it can request. The model never executes them itself — it asks, and your code runs them. First appears: Stage 3
Transport (stdio / HTTP)
How the client and server talk. stdio launches the server as a local subprocess; HTTP connects to a server already running independently (local or remote). First appears: Stage 5
